객체지향을 클래스·상속 문법으로 배우면 함수형으로 기우는 React와는
관계없는 이야기처럼 들린다. 그런데 객체지향이 풀려던 문제를 한 꺼풀
벗겨보면 이렇게 요약된다.

> 타입에 따라 행동이 달라질 때, 그 분기(if)를 누가 소유하는가.

분기를 호출하는 쪽이 소유하면 같은 if가 호출부마다 복제되고, 새 타입이
추가될 때마다 흩어진 if를 전부 찾아다녀야 한다. 다형성은 그 분기를
**타입 자신의 뒤로 숨기는** 기술이고, 이건 클래스 없이도 성립한다.

## 사례: 글 대표 이미지

이 블로그의 글 목록 카드에는 대표 비주얼이 있다. 글에 썸네일이 있으면
그 이미지를, 없으면 제목을 박은 타이틀 카드를 자동 생성해 보여준다.

이 분기를 소비자가 소유하면 이렇게 된다.

```tsx
// 카드에서
{post.thumbnail ? <Image src={post.thumbnail} ... /> : <TitleCard post={post} />}
// 홈 피처드에서도
{post.thumbnail ? <Image src={post.thumbnail} ... /> : <TitleCard post={post} />}
```

카드, 피처드, 나중에 생길 OG 이미지 — 쓰는 곳마다 같은 삼항이 복제된다.
"썸네일이 없으면 어떻게 보이는가"라는 정책이 바뀌면 전부 고쳐야 한다.

그래서 분기를 컴포넌트 경계 뒤로 넣었다.

```tsx
export function PostCover({ post, sizes }: { post: PostMeta; sizes: string }) {
  if (post.thumbnail) {
    return <Image src={post.thumbnail} alt="" fill sizes={sizes} />;
  }
  return <TitleCover post={post} />;
}
```

소비자는 이제 분기의 존재를 모른다.

```tsx
<PostCover post={post} sizes="150px" />
```

if는 여전히 존재한다 — **한 곳에, 그 분기를 소유해야 할 개념의 이름
아래에.** `PostCover`는 사실상 인터페이스고, 이미지와 타이틀 카드는
그 구현체다. 클래스 다이어그램 없이도 다형성의 효용(분기의 단일 소유)은
그대로 얻는다.

## 상속이 아니라 조합인 이유

전통적 OOP라면 `Cover`를 상속한 `ImageCover`/`GeneratedCover`를 떠올릴
수 있다. React가 조합을 택한 건 취향 문제가 아니다. 상속 계층은 축이
하나다 — "커버의 종류"로 한 번 나누면, "크기 변형"이라는 두 번째 축이
생겼을 때 계층이 폭발한다(`CompactImageCover`, `CompactGeneratedCover`…).

조합은 축을 독립적으로 둔다. 이 블로그의 실제 코드에서 `compact`는
상속이 아니라 prop이고, 커버 종류와 자유롭게 곱해진다.

```tsx
<PostCover post={post} sizes="150px" compact />
```

## 언제 과잉인가

분기가 한 곳에서만 쓰인다면 컴포넌트로 감싸는 것 자체가 간접층 비용이다.
이 사례도 처음 카드 하나만 있을 때는 삼항으로 뒀고, 피처드가 같은 분기를
복제하려는 순간에 `PostCover`로 뽑았다.

객체지향의 도구들은 전부 **변경을 한 곳에 모으는 장치**다. 변경이
한 곳뿐이면 장치가 필요 없다. 두 번째 복제가 생기는 순간이 추상화의
타이밍이다.
